# Security

Use the latest published release and keep backups of important designs. This early
project does not promise a response SLA or support for older versions.

## Reporting a vulnerability

If enabled, use GitHub's **Security → Report a vulnerability** for a private report.
Include the affected version, impact, and a minimal reproduction. Do not post
credentials, private files, or exploit details in a public issue.

If private vulnerability reporting is unavailable, open an issue requesting a
private contact method without describing the vulnerability. Wait for a private
channel before sharing sensitive details.

Machine safety is separate from software security. Use your manufacturer's
instructions and safety equipment, inspect jobs before running them, and do not
depend on this software as a safety interlock.
